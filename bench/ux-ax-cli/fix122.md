### What I ran

```bash
swift build -c release            # HEAD a438e9c
.build/release/krd --nonsense     # (1)
.build/release/krd --fps          # (2) missing value
.build/release/krd --fps abc --demo   # (3) non-numeric value
.build/release/krd ax --nonsense  # (4) for contrast
```

Each was wrapped in a hard timeout (macOS has no `timeout(1)`; used `perl -e 'alarm 8; exec @ARGV'`),
stdin from `/dev/null`.

### Expected

```
$ krd --nonsense
krd: unknown option "--nonsense" (try `krd --help`)
$ echo $?
2
```

README documents `2` = usage (`README.md:112`), and `krd ax` already behaves exactly this way
(`Sources/krd/AXCommand.swift:152`).

### Actual

`(1)`, `(2)` and `(3)` **launch the desktop mirror** — no diagnostic, no usage text, no error exit.
They allocate the alternate screen, paint the wall, and block on input until something kills them:

```
$ krd --nonsense </dev/null
rc=142 (SIGTERM from the wrapper, 8 s later)
stdout = 4665 B of kitty-graphics frames:
  ESC_Ga=d,d=i,i=31 ESC\ ESC[?2026l ESC[?1003l ... ESC[?1049h ESC[2J ESC[H ESC[?25l
  ESC_Ga=d,d=a ESC\ ESC[2J ESC[1;1H ESC[1;97m▪ krd ESC[2;37m    5 windows · 3 displays ...
stderr = 0 B
```

`(3)` is worse than a hang: `--fps abc` silently falls back to the default rate and streams
32 330 B of frames instead of saying "abc is not a number". `--fps` with no value does the same
(`--fps` reads `args[safe: i+1] ?? ""` and `?? options.fps` — `Sources/krd/main.swift:337`).

Contrast, same shell, one word of difference:

```
$ krd ax --nonsense ; echo rc=$?
unknown option "--nonsense" (try `krd ax --help`)
usage: krd ax [options] <command>
...
rc=2
```

So the two flag parsers in the same binary disagree on whether unknown input is an error.

### Why it costs a user/agent

- An agent that mistypes one flag (`--fps- 20`, `--dryrun`, `--mirror-mode`) gets a **success-looking
  long-running process that streams the user's screen to stdout**. The failure mode is not "wrong
  output", it is "captures the desktop and never exits". For an unattended caller that is worse than
  a crash: it has to be killed, and there is nothing in the exit status or stderr to explain why.
- `krd` is documented as scriptable (`--no-chrome`, `--stats-json`, `--list`, `--json`), so
  "typo → visible desktop stream" is reachable from any wrapper script.
- `main.swift:505` (`default: break`, the top-level switch) is the general case: every unknown
  top-level token is dropped on the floor. `krd --list --json` is the proof on the lossless side —
  it exits 0 and prints byte-identical output to `krd --list` (3 073 B), so `--json` is silently
  swallowed rather than rejected. `--version junk` is accepted too (`krd 0.1.2`, rc 0) because
  trailing positionals are ignored.

### Proposal (smallest change)

In `parseArguments` (`Sources/krd/main.swift:330`), mirror what `AXOptions.parse` already does
(`Sources/krd/AXCommand.swift:152`):

1. In the `switch flag` `default:` at `main.swift:505` — instead of `break`, record
   `unknownFlag = flag`; after the loop, if `unknownFlag != nil` print
   `krd: unknown option "<flag>" (try `krd --help`)` to stderr and `exit(2)`.
2. For value-taking flags (`--fps`, `--display`, `--zoom`, `--quality`, `--cell`, …) require
   `i + 1 < args.count` and a parseable value; on failure print
   `krd: --fps needs a number (got "<v>")` and `exit(2)`.
3. Keep the documented internals (`--wall-at`, `--said`) in the known-flag list — they are already
   in `--help` (`main.swift:223-229`), so the set stays complete.

Cost/risk: ~25 lines, no behaviour change for valid invocations; the only users who can notice are
those currently relying on a typo being ignored. A stricter subset (reject unknown `--*` only, keep
positionals ignored) is enough to close the dangerous case and is ~8 lines.

### Correction (after an independent review of this issue)

Two things a reviewer found that make the case stronger, both re-measured:

- krd **traps SIGTERM and exits 0**. Three separate hung runs of (1)(2)(3) returned `rc=0` once
  signalled, not `rc=143`/`142`. So a wrapper script that applies its own timeout and kills the
  mistyped mirror records **success** — the typo is invisible in the exit status as well as stderr.
- The author already knows this class of bug for one flag. `main.swift:347-349` on `--scale`:
  *"The parser does not throw; an unparsable value is carried to `run()` instead of silently meaning
  "1", because a typo here doubles the bytes on the wire."* `--fps` (`:337`) and the unknown-flag
  `default:` (`:505`) did not get the same treatment.

### Alternatives considered

- Reject only when stdin is not a tty. Cheaper to argue, but leaves the interactive typo case
  broken and makes exit codes depend on the environment.
- Print a warning and continue. Still captures the desktop; does not fix the agent case.

`--json` silently changes `ax doctor`'s exit code — that is filed separately so this one stays
one defect with one repro.
