### What I ran

Screen was locked (frontmost app `loginwindow`), so the AX API answered `cannotComplete` for every
read — which turns out to be the perfect probe for the *error* half of `--json`:

```bash
.build/release/krd ax doctor           # text
.build/release/krd ax doctor --json    # same condition, --json
.build/release/krd ax windows --json
.build/release/krd ax tree --app Finder --json
.build/release/krd ax find zzzznomatch --json
```

### Expected

`--json` is a *format* switch: same exit code as text mode, and one JSON object on stdout in every
outcome — success or failure — so a caller can `jq -e '.ok'` and branch on `.error.code`:

```json
{"ok": false, "error": {"code": "cannotComplete", "exit": 4,
                        "message": "the accessibility API is not answering",
                        "next": "the Mac may be asleep or at the login window"}}
```

### Actual

Same failure, two different exit codes, and no JSON at all on the failure path.

```
$ krd ax doctor ; echo rc=$?
accessibility permission  granted
accessibility answers     no (cannotComplete)
window server             24 windows on screen
first call in this process cannotComplete → retry cannotComplete
frontmost app             -
krd ax: the accessibility API is not answering (cannotComplete)
...prose...
rc=4

$ krd ax doctor --json ; echo rc=$?
{"answers":false,"error":"cannotComplete","firstCall":"cannotComplete","onScreenWindows":24,"sample":"-","trusted":true}
rc=0
```

`--json` here is a *monitoring* flag, and monitoring means the exit code is the signal. `doctor`
in JSON mode reports `"answers":false` and then returns success
(`Sources/krd/AXCommand.swift:411-412` — `if options.json { return AXExit.ok.rawValue }`) before the
`answers ? ok : environment` line it skips. So `krd ax doctor --json && krd ax windows` is green
then red on the same broken machine, and any cron/health-check that uses `--json` to get parseable
output gets a permanently-passing check.

And for the commands that *do* fail, `--json` produces **zero bytes of stdout** and 273 bytes of
English prose on stderr:

```
$ krd ax windows --json >/dev/null ; echo rc=$?      # 4
$ krd ax windows --json 2>/dev/null | wc -c
0
```

An agent that only parses stdout cannot tell "no windows" (`rc=0`, empty array) from "the API is
dead" (`rc=4`, empty stdout) without also scraping stderr prose that is explicitly written for a
human ("the Mac may be asleep or at the login window").

### Why it costs a user/agent

- `krd ax` is the surface an AI agent drives with no render loop, and `--json` is the only
  machine-readable channel. Right now: success is JSON, failure is prose, and one command's exit
  code changes meaning when you ask for machine output. Every caller has to special-case both.
- The four failure classes the design already distinguishes (`3` no permission, `4` window server,
  `5` nothing matched, `6` refused/read-back-differs) are exactly the ones a script needs to branch
  on — grant TCC, retry, widen the query, report a UI bug. All four are prose-only today.
- `docs/research-ax-text-channel.md` claims agent-friendliness as a goal (§ "结构化输出、可发现性、
  非交互") — this is the gap between that goal and the surface.

### Proposal (smallest change)

One error shape, one place, emitted whenever `options.json` is set — in the `catch` at
`Sources/krd/AXCommand.swift:104-115`, before `exit(failure.code.rawValue)`:

```swift
if options.json {
    print(AXText.json(["ok": false, "error": ["code": failure.codeName,
                                             "exit": failure.code.rawValue,
                                             "message": failure.message]]))
}
```

and drop the `if options.json { return .ok }` shortcut at `:411` so `doctor --json` returns the same
code as `doctor`. Cost: ~30 lines (a `codeName` on `AXFailure`, one encoder call). Risk: a caller
that currently relies on `doctor --json` exiting 0 would change behaviour — that is the bug, but it
belongs in the changelog. Alternative, cheaper and non-breaking: leave `doctor` alone, add the
`.ok:false` object only in the catch, and document the exit-code table for `--json` — but then the
"green doctor on a broken Mac" stays.

### Notes / not proven

`krd ax tree --json` on a *working* AX backend was not captured: the screen was locked for the whole
session (`cannotComplete` on every read), so I could not check whether the success shape is stable
across dumps (field order, refs) or whether it leaks ANSI. That part of the survey is reported as
unproven rather than asserted.
