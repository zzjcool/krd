### What I ran

```bash
.build/release/krd --list </dev/null | head -c 64 | xxd
.build/release/krd --list </dev/null | LC_ALL=C grep -c $'\x1b'
.build/release/krd ax windows        # the other window listing
```

### Expected

`--list` is the documented "what can I point `--display`/`--window` at" command (`krd --help`:
"list displays and windows, then exit") and it is the discovery step a script runs *before* it does
anything else. Its stdout should be pure text — and, like the rest of the headless surface, it
should have a `--json` form.

### Actual

The first bytes on stdout are a kitty-graphics escape, not text:

```
00000000: 1b5f 4761 3d64 2c64 3d69 2c69 3d33 311b  ._Ga=d,d=i,i=31.
00000010: 5c20 2020 2077 696e 646f 7720 3133 3231  \    window 1321
00000020: 3239 2020 402d 3135 3030 302c 2d31 3530  29  @-15000,-150
```

i.e. `ESC _ G a=d,d=i,i=31 ESC \` followed immediately by `    window 132129 ...`. It is the
"delete image 31" cleanup in `Sources/krd/Geometry.swift:180`, emitted unconditionally at startup,
before the program knows it is only going to print a list and exit.

So `krd --list | awk '{print $2}'` returns `_Ga=d,d=i,i=31\` on the first line, and a terminal that
does not speak the kitty protocol prints the sequence literally. `grep -c $'\x1b'` on the output is
`1` — there is exactly one control sequence and it is in a command whose entire job is text.

Other shape problems in the same output:

- 38 lines of raw window records (count varies with how many displays/windows are live) with no header,
  no column alignment between the first and the rest,
  and no stable separators (`$4` is sometimes the app, sometimes `@x,y`).
- It includes windows a script can never target: `window 132129  @-15000,-15000 30000x30000
  app=loginwindow title=-`, three `Display N Shield` windows (132204/205/206), `Offscreen Wallpaper
  Window`.
- `--list --json` is silently accepted and prints byte-identical text (3 073 B) — the flag exists
  everywhere else on this surface, so an agent will reasonably assume it works here too.
- There is no `--json`, so this is the one listing an agent cannot parse reliably — while the
  *other* listing, `krd ax windows`, has `--json` and a different column set. Two listings, two
  formats, one of them machine-readable, neither documented as the canonical one.

### Why it costs a user/agent

The very first command in any "find an app and mirror it" script is `--list`. Today that script
either has to strip a binary escape (undocumented, and it moves if the cleanup ever changes) or
switch to `krd ax windows`, which needs Accessibility and returns a different schema. And because
`--json` does not exist here, the discovery step is the only one in the headless surface that
cannot be done without text munging.

### Proposal (smallest change)

1. Emit the `Ga=d,d=i,i=31` cleanup only on a path that actually painted (it exists to drop a stale
   image from a previous run of *this pane*); `listOnly` is decided before anything is drawn
   (`Sources/krd/main.swift:502`, consumed at `:948`), so the guard is one condition near
   `Geometry.swift:180`.
2. Add `--list --json`: a single object
   `{"displays":[{"index":0,"width":1728,"height":1117,"main":true}],"windows":[{"id":128444,
   "app":"Rex Beta","title":"Shell - …","frame":[15,559,161,158],"targetable":true}]}`, reusing
   the same window records `krd ax windows --json` already builds, plus the `targetable:false` flag
   for the shields/off-screen windows (the code already knows: `main.swift:2603` marks them).

Cost/risk: ~40 lines, no capture-path change; the escape guard is the risky bit (it must not skip
the cleanup when a mirror really is being replaced). Alternative: keep one listing only — point
`--list` at `ax windows` internally and delete the duplicate formatter, at the cost of making
`--list` require Accessibility, which it happily does not need today.
