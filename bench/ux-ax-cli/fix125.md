### What I ran

```bash
.build/release/krd --help | grep -i exit
.build/release/krd ax --help | tail -5
.build/release/krd ax doctor        # with the AX API answering cannotComplete
grep -n "exit" README.md README.zh-CN.md docs/TROUBLESHOOTING.md
```

### Expected

One exit-code contract, stated once, identical wherever it is stated, and the six codes the enum
actually has (`Sources/krd/AXCommand.swift:18-33`: `0 ok · 2 usage · 3 permission · 4 environment ·
5 notFound · 6 notActionable`) visible from the entry point a new user/agent reads first.

### Actual

Three sources, three answers, and the entry point says nothing.

1. **`krd --help`** — no exit-code section at all; the only mention is a pointer buried in the
   `ax` block, rendered as help line 92 (`main.swift:244` in source):
   "(`krd ax --help` for the full surface and the exit codes)").
   An agent that starts from `--help` and greps for "exit" gets `--list … then exit`,
   `--version … and exit`, `--bench … then exit` and nothing about status codes.

2. **`krd ax --help`** — the complete table, but only here:
   `exit: 0 ok · 2 usage · 3 no accessibility permission · 4 window server unreachable` /
   `5 nothing matched · 6 node refused the action, or read back something else`.

3. **README.md:112-113 and README.zh-CN.md:92-93** — `0/2/3/4/5`. **Code 6 is missing in both
   languages**, and 6 is the one a caller must handle to know a write landed: `press` on static
   text, `set` on a read-only field, or `set` where the app read back something else
   (`AXCommand.swift:30-32`). The only other mention in the whole tree is a passing sentence in
   `docs/TROUBLESHOOTING.md:660` ("the exit code is `6`"), with no table to put it in.

Same class, in the error text itself — the failure advice points at the command you are already
running:

```
$ krd ax doctor
accessibility permission  granted
accessibility answers     no (cannotComplete)
...
krd ax: the accessibility API is not answering (cannotComplete)

The binary is trusted, so this is the window server, not a permission: the Mac may
be asleep or at the login window, or every app that could answer is hung.
Run `krd ax doctor` to see which of the two it is.        <-- you are running `krd ax doctor`
```

For `krd ax windows` that sentence is exactly right; for `doctor` it is a loop. Same for
`krd ax tree --app X` when there is no `--app`-less fallback: the tail advice is identical, so the
one line that should differ per verb is the one that never does.

### Why it costs a user/agent

`README.md` is the first thing a new user reads and `krd --help` is the first thing an agent reads.
Both currently teach a 5-code contract that the binary does not honour, so a caller tuned to the
docs treats `6` as "unknown failure, probably exit 1-ish" — in practice it means "the write was
sent and the app did not take it", which is the difference between retrying and reporting a bug.
The self-referential advice costs a debugging loop on the one machine state (locked/asleep) where
the agent can do nothing but must report precisely.

### Correction (after an independent review)

Two line-number slips, both fixed above: the `--help` pointer is source line `main.swift:244`
(help line 92 is its rendered position), and the enum spans `AXCommand.swift:18-27` — `29+` is
`AXFailure`. The claim itself is unchanged: the enum has six cases, README documents five, both
languages.

### Proposal (smallest change)

- `README.md:112` + `README.zh-CN.md:92`: add `6` with its meaning (`press`/`set` refused the
  action, or the value read back differs).
- Add the same two-line table to the end of `krd --help` (after the `headless:` block,
  `main.swift:~230`), so the contract is visible without a second command; keep the pointer to
  `ax --help` for detail.
- In the shared AX failure printer (`AXCommand.swift:~104-115`), print the "Run `krd ax doctor`"
  sentence only when the failing verb is not `doctor`; for `doctor` print the actionable half
  ("wait for the Mac to wake, or log in; then re-run") instead.

Cost/risk: docs + 4 lines of string logic, no behaviour change. Alternative for the last point:
make the advice generic ("see docs/TROUBLESHOOTING.md §37, §38") — cheaper, but loses the
per-verb precision that makes the current message good for `windows`.
